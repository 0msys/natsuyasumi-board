# 子どもと年度の管理

## 一覧

子どもごとに、現在選ばれる年度の学年、期間、始業式、ほかの年度を表示します。
現在選ばれる年度だけを検証します。
その年度が壊れている場合はエラー内容を表示し、来年度作成を無効にします。
未選択の年度は一覧では検証しません。

## 年度の選択

1人の子どもに複数年度を登録できます。
子どもページで使う年度の決め方は[日付・期間・年度](../common/dates-years.md)を参照してください。
編集画面では年度タブまたは `year` クエリで対象を指定します。

## 来年度の作成

最新年度から1年後の定義を作ります。

- 学年を1つ上げます。小6の定義からは作成できず、400エラーを表示します。
- 夏休み期間、始業式、新学期準備の期限を1年後へ移します。
- 設定項目とラベルを引き継ぎます。
- 記録に使う項目キーは新しくします。
- チェック、宿題完了、選択判断などの記録は引き継ぎません。
- 外出予定は空にします。
- 作成前に確認を表示します。

同じ年度がすでにある場合は作成できません。
作成元になる最新年度が壊れている場合は、一覧でエラーが出ていなくても422エラーを表示します。

## 名前変更

- 新しい名前を入力し、確認後に変更します。
- 前後の空白は除きます。
- 定義だけでなく、その子どもの記録も新しい名前へ移します。
- 空の名前と、すでに使われている名前は拒否します。
- lite版では、変更先に定義がなくても、削除済みの子どもの記録や定義履歴が残っていれば409エラーで拒否します。
- Docker版では残存記録を事前確認しません。同じ記録キーが衝突した場合は、データベース制約で変更全体を中止します。

## エクスポート

- 一覧で選ばれている年度の定義を JSON で保存します。
- ファイル名は `{年度}-{子ども名}.json` です。
- 実行中は、ほかの子どもを含む全エクスポートボタンを無効にします。
- ブラウザへ渡した後、保存できなかった場合に備えて再ダウンロードリンクを表示します。

チェック記録は定義エクスポートに含みません。

## 定義の削除

- 一覧からの削除は、その子どもの全年の定義を対象にします。
- 複数年度がある場合、編集画面の「この年をけす」は表示中年度だけを対象にします。
- 一覧では子ども名の再入力を必須にします。
- 定義を削除してもチェック記録は物理削除しません。
- 表示対象の定義がなくなると、子どもページには出なくなります。

## テスト観点

- 複数年度の表示と編集対象の切り替え
- 来年度作成の日付、学年、キー、外出予定
- 未選択の最新年度が壊れている場合に来年度作成を422で拒否すること
- 小6からのコピーを拒否すること
- 既存年度との重複拒否
- 名前変更による全記録の移動
- lite版で変更先に残存記録または定義履歴がある場合の409エラー
- Docker版で残存記録のキーが衝突した場合に変更全体を中止すること
- エクスポート中の多重実行防止と再保存リンク
- 全年削除と、複数年度がある場合の単年度削除の違い
- 削除後も記録が残ること

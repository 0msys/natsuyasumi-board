# バックアップと復元

## 対象

端末全体のバックアップは lite 版だけで表示します。
Docker 版はサーバ側のデータ領域を別途バックアップします。

1年度分の「定義エクスポート」は両版で利用できますが、チェック記録を含みません。

## lite 版のバックアップ

すべての定義、チェック記録、タイマー、管理用メタ情報を1つの JSON に保存します。

- 初回未実施、前回からの変更数、経過日数、保存領域の状態から案内レベルを決めます。
- 子どもページでは文言を出さず、設定の歯車に印を付けます。
- 設定一覧では理由と操作を表示します。
- ホーム画面から起動していない端末では、ホーム画面への追加を案内します。メモリ退避のときは保存領域の警告を優先し、この案内を出しません。
- 案内は閉じられます。閉じたあとは再表示しません。閉じた操作はバックアップ対象の変更数に含めません。

## 保存完了の確認

ファイルをブラウザへ渡しただけでは、前回バックアップ日時を更新しません。

1. 「バックアップする」でファイルを作ります。
2. ダウンロードされたことを利用者が確認します。
3. 「ほぞんできた」で完了を記録します。

保存できなかった場合は完了にせず、再実行を促します。
書き出し後にデータが変わっても、書き出した時点のバックアップとして完了を記録します。
書き出し後の変更は、未バックアップの変更数に残します。
保存領域の世代が異なる場合、通番が現在より先または確認済み基準より前の場合、書き出し時刻が未来の場合は完了を拒否します。

## 復元

- バックアップ JSON を選び、全データを置き換える確認を表示します。
- 同意した場合だけ現在の端末データを置き換えます。
- 復元前に、未確認のバックアップ完了確認を破棄します。
- 形式不正、必須データ不足、未対応の新しい版は拒否します。
- 同じファイルを選び直せるよう、ファイル入力は毎回初期化します。

設定一覧の「JSON をインポート」は内容を判定します。
端末バックアップなら全置換、定義 JSON なら新規定義として取り込みます。
全置換は lite 版だけの機能です。
Docker 版で端末バックアップを選ぶと確認後に501エラーで拒否します。
同じ子ども・同じ年度の定義がある場合は定義インポートを拒否します。
同じ子どもの別年度が登録済みで、その年度と項目キーが重なる場合は、取り込み時に項目キーを新しくします。
重ならない場合は項目キーをそのまま保ちます。削除した年度を書き出した JSON から登録し直すと、
残っている記録に再び結び付きます（[子どもと年度の管理](admin-child-management.md#定義の削除)）。

## 保存領域の警告

IndexedDB を使えずメモリ退避になっている場合は、すべての管理画面上部へ警告を表示します。
この警告は初回ウィザードにも表示します。
保存の持続要求を使えない端末や、要求を断られた場合は警告を出しません。判定に使うのはメモリ退避かどうかだけです。

## テスト観点

- Docker 版で端末バックアップを表示しないこと
- 書き出しただけでは完了日時を更新しないこと
- 保存確認後だけ日時と変更数を更新すること
- 書き出し後の変更を未バックアップ件数に残すこと
- 異なる保存世代、範囲外の通番、未来時刻を拒否すること
- 復元の確認取消時にデータを変えないこと
- 全データ置換と定義追加の振り分け
- Docker 版で端末バックアップの復元を501で拒否すること
- 壊れた形式、新しい版、同一年度の定義を拒否すること
- 別年度と重なる項目キーだけを振り直し、重ならない場合は保つこと
- 保存領域警告が全管理画面に出ること

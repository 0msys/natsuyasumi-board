# 保存方式と版の違い

## 共通部分

画面、採点ルール、定義検証、管理機能は両版でほぼ同じです。
Python の計算結果を金型にし、TypeScript 版との一致をテストします。

定義検証のうち、lite 版だけが持つ追加の制約は「[lite 版だけの検証](#lite-版だけの検証)」に書きます。

## Docker 版

- 定義と記録をサーバの SQLite に保存します。
- 画面は `/api` を通して読み書きします。
- 複数端末で同じ記録を共有します。
- 子どもページは60秒ごとに全状態を更新します。
- テレビタイマーは5秒ごとに更新します。
- VOICEVOX があれば音声読み上げを利用できます。
- 管理 API は PIN または明示した PIN なし運用で保護します。

## lite 版

- 定義、記録、タイマーをブラウザの IndexedDB に保存します。
- 採点と検証は TypeScript で実行します。
- データは別端末へ同期しません。
- 音声読み上げは利用できません。
- 管理 PIN はありません。
- 全データの JSON バックアップと復元を利用できます。

### lite 版だけの検証

記録は「子ども名・日付・項目キー」を区切り文字でつないだ1つのキーで持ちます。
区切り文字そのものが名前や項目キーに入ると、書けたはずの記録を読み出せなくなります。
Docker 版は SQLite の別々の列へ入れるため、この制約はありません。

- 定義の作成とインポートでは、子ども名・毎日の項目キー・フラグ項目キーに区切り文字が入っていれば422で拒否します。
- 名前変更では、新しい名前に区切り文字が入っていれば400で拒否します。
- 画面から打てる文字ではないため、通るのは手書き JSON の取り込み経路だけです。

## 保存の永続性

lite 版はブラウザの保存領域に依存します。
IndexedDB を使えずメモリ退避になっている場合だけ、管理画面のどのページでも上部へ「記録が保存されない」警告を表示します。
保存の持続要求は1セッションに1回だけ裏で行い、結果を保存します。使えない端末や断られた場合でも警告は出しません。親に打つ手がないためです。
ホーム画面へ追加していない場合は、設定一覧で追加を案内します。案内は閉じると再表示せず、メモリ退避のときは警告を優先して表示しません。

## 更新の整合性

- 日次操作の成功後は状態全体を再計算・再取得します。
- Docker 版の定義保存は revision による楽観ロックを使います。
- 子どもの切り替えをまたいだ古い応答は破棄します。
- 通信ポーリングに失敗しても、直前の表示を消しません。
- 年度ごとの項目キーを分け、前年の完了記録を誤って再利用しません。

## オフライン

lite 版は静的ファイルを Service Worker で保持し、インストール後はサーバなしで動作できます。
Docker 版も採点に外部サービスや LLM を使いません。音声だけが任意の VOICEVOX に依存します。

## テスト観点

- 同じ入力に対する Python と TypeScript の金型一致
- Docker 版の複数端末反映
- lite 版で端末間同期しないこと
- lite 版で区切り文字を含む名前・項目キーのインポートを422で拒否し、Docker 版では拒否しないこと
- lite 版で区切り文字を含む名前変更を400で拒否すること
- lite 版の再読込後も IndexedDB の値を保持すること
- メモリ退避のときだけ保存警告を出し、持続要求が使えない・断られた場合は出さないこと
- ホーム画面追加の案内が、閉じたあととメモリ退避のときに出ないこと
- revision 競合と古い応答の破棄
- Service Worker の必須資産とフォールバック
- VOICEVOX 不在でも音声以外が動くこと
